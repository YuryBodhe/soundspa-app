### Music playback — IMPLEMENTED BUT NOT FULLY VERIFIED

Committed HEAD `4fa613a` implements a hybrid architecture:

1. Network-backed `HTMLAudioElement` provides progressive HTTPS playback.
2. Startup waits for 5 contiguous buffered media-seconds before audible playback.
3. Public `playing` requires real `currentTime` progression, not only a resolved `play()` or `playing` event.
4. Buffer health is monitored as healthy/low/critical using the buffered range containing `currentTime`.
5. Audible network loading has priority over full-file cache fetching.
6. Full MP3 downloads become Blob URLs in two in-memory reusable slots.
7. `desiredNextIndex` tracks logical playlist progression independently of cached slot identity.
8. Cache requests use `AbortController`, a generous 10-minute timeout, request/generation validation, retry backoff, and Blob URL cleanup.
9. Pause preserves the active position and cached Blobs. Since `76dc20f`, already-authorized A/B preparation may continue while paused.
10. Network→same-track Blob handoff exists for prolonged, non-progressing network playback when the same-track Blob is complete.

Divnitsa currently has three logical playlist URLs:

- `/music/divnitsa/divnitsa-mix-01.mp3`
- `/music/divnitsa/divnitsa-mix-02.mp3`
- `/music/divnitsa/divnitsa-mix-03.mp3`

`Relax` and `432 Hz` remain UI-only; they do not have real music playback.

### Ambient playback — IMPLEMENTED BUT NOT FULLY VERIFIED

Committed in `7a30ffb`:

1. Uncached selected ambient begins through its progressive network URL immediately.
2. The same selected file is fetched fully in the background.
3. Completed ambient files are retained as Blob URLs in an in-memory LRU cache with maximum 3 entries.
4. The active ambient entry is protected from eviction.
5. Duplicate fetches are avoided; rapid switching and stale completion use generation/identity protection.
6. Once a selected network ambient reaches its natural loop boundary and its Blob is ready, the next pass switches to the Blob and loops locally.
7. Music and ambient remain independent.

Current ambient IDs/URLs from `V2Player.tsx` are `/noise/forest.mp3`, `/noise/night.mp3`, and `/noise/sea.mp3`.

## 7. Known issues

### KNOWN BUG — mid-playback buffer exhaustion without a complete Blob

Reproduction:

1. Start Divnitsa online.
2. Let audible playback begin before Blob A completes.
3. Disconnect internet.
4. Browser plays its existing media buffer.
5. Buffer exhausts and playback freezes/stops.
6. Restore internet.

Observed result: no automatic recovery; explicit Play does not recover; page reload is required.

Root cause in committed `4fa613a`:

- the 10-second network stall handler can hand off to a complete same-track Blob or another complete cached Blob;
- when no Blob exists, that handler has no network-source recovery action;
- a mid-playback media `error` can still reach terminal `handlePlayError()`, which clears `wantsPlayback`;
- explicit Play may reuse the terminal failed `HTMLAudioElement` rather than fully recreating it.

## 8. Important decisions and why

1. **Progressive network audio first.** Waiting for an entire ~30 MB track caused unacceptable first-sound latency.
2. **Full Blob cache in parallel.** Complete tracks provide resilience after network loss without requiring Service Worker or persistent storage.
3. **Five media-seconds, not a fixed wall-clock delay.** Fast connections can start quickly; startup readiness uses actual contiguous buffered media.
4. **Actual `currentTime` progression defines audible playback.** Browser events/promises can report playing while media is frozen.
5. **Audible bandwidth has priority.** Full-track fetch is deferred/aborted when buffer health deteriorates.
6. **Two reusable music Blob slots.** This bounds normal music memory while enabling A/B fallback.
7. **Logical playlist target is separate from audible fallback.** Playing any cached track to avoid silence must not lose the intended track/position to recover.
8. **Local playable audio beats network retry.** A complete Blob should be used before accepting silence while repeatedly testing the network.
9. **`navigator.onLine` is only a hint.** Actual media/fetch success proves connectivity.
10. **Ambient has a small LRU, not A/B preloading.** Around ten future ambient channels must not all be loaded; cache only selected/recent sounds, maximum three.
11. **No premature platform expansion.** No HLS/DASH, MediaSource, Service Worker, IndexedDB, crossfade, DRM, heartbeat, or new auth system during the playback reliability phase.
12. **Production isolation is non-negotiable.** Active salons use v1; all experiments stay local/staging.
